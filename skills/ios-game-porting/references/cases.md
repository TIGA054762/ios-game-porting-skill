# 匿名化排障案例

这些案例仅证明当时的测试范围；项目版本、系统、设备和具体数据会影响结果。运行环境不同需要重新验证。

## 大型游戏侧载

- 一个大型游戏的完整 IPA 在侧载时出现解包失败。只外置 ROMFS 后包内条目数量仍很高；按该宿主的实际目录约定进一步外置着色器后，精简包安装成功。另一个游戏仅外置 ROMFS 即完成安装。不要把其中任一种处理套用到所有 App。
- 大文件通过设备文件共享分块传输，对已有前缀和设备端哈希做校验。电脑和设备用相同哈希算法比较；长度一致不等于内容一致。

## 着色器与画面

- 某些片元 shader 的输出类型与无符号整数颜色附件不匹配。仅修复所涉及的 shader，重新编译、回传校验后，原故障场景得到确认；没有验证全部场景。
- 某游戏的启动程序曾向旧版 SDK 返回超过游戏容器容量的语言列表，导致启动陷阱。针对 SDK 能力修复并测试后可进入游戏；同样的闪退信号可能有其他根因，需结合堆栈与版本判断。
- 一次黑闪在 Standard 和 MetalFX 都出现；多项设置调整与底层画面提交对照后，用户反馈黑闪消失或明显减少。由于测试条件并非全部一致，不能据此宣称找到单一根因。

## 存档与帧率

- 一次跨引擎存档迁移先分别备份、核对游戏版本并检查目标，传输后校验文件，由玩家确认进度正确。不同游戏和引擎可能有完全不同格式。
- 某 30 帧游戏测试社区补丁的防空指针改写后，游戏速度或帧率不稳定，停用后需要完全退出重启，再验证恢复。此经验不意味着所有该游戏的 60 帧实现均不可用。
- 截图后短时间切出并返回曾成功；这不保证系统在长时间后台或内存压力下不会回收应用。
