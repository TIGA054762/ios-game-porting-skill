# 已踩过的坑与排查方法

## 安装与资源

- 完整 IPA 的大文件、ZIP64 和海量 ZIP 条目可能影响个别侧载工具，但先看实际报错。曾有卡比完整包 `PackageExtractionFailed`，只外置 ROMFS 仍约 9.1 万条目；进一步按宿主支持拆出 shader 后精简 IPA 成功。不是所有游戏都应拆 shader。
- 火焰纹章的分体准备仅外置 ROMFS，曾核对 4,536 个保留 shader；安装及进场由用户确认，重启存档与 DLC 不能凭此断定完整通过。
- 用户曾问 403 MB 包为什么不像十几 GB：IPA 是宿主，主体和 DLC 可能外置；以代码和运行日志确认挂载、数据大小与哈希。不能凭体积判断缺失。
- Windows 能看到 iPad 不代表签名工具已连接；核对 Apple 设备服务、信任和解锁。HouseArrest 的 `documents_only=True` 下 `/` 曾 PERM_DENIED，而 `/Documents` 可用。签名后的 bundle ID 可能有后缀，先枚举真实目标，不能沿用另一游戏 ID。读写大文件用块传输、校验前缀与结果。
- 合理备份 AltStore 将要停用的 App 的最新存档。不要把安装中进度、应用存在、哈希匹配、读档成功混成同一个结论。

## 构建和着色器

- XB2 旧构建 15,910 个着色器曾运行数小时；99% 最后一个耗时不代表卡死；同时构建另一套会争用资源。根据日志、进程与缓存变化判断，不擅自中止。
- `cas.db` 与 WAL/SHM 共同保存；中断时缓存一致性及下次命中由引擎实际判断，不要删 WAL 或声称计数必然全命中。
- 卡比曾有 147 个片元 shader 对 `R8Uint` 输出类型不匹配，定点修复后编译与传输哈希通过，用户确认原故障场景恢复，不代表全游戏无问题。不要用此修复覆盖其他游戏。
- Windows Metal 旧版本曾在中文路径无法创建 AIR：按当时做法用英文工作路径，现有版本先验证；日志错误、返回码和编译器版本比泛泛猜测更重要。
- 旧 NX2Apple 的 shader 库、运行时 GPU pipeline 缓存、S2Arm 的渲染与缓存格式各不相同；不要把“着色器已编译”理解为所有渲染路径一致或永无卡顿。

## XB2 语言、存档和闪退

- 日版 2.0.2 曾发生 `CRASH sig=5 main+0x6979dc`，修复记录指出 SDK 3 游戏使用 15 项语言容量，而宿主返回了 18 项。专用修复版约束列表数量，用户后来确认成功读到迁移存档。不要误装修复前的 `..._test.ipa`；修复版为 `..._language_fix.ipa`，重新核对哈希、版本和实际运行日志。
- 游戏的文本语言、语音语言和地区资源不同；启动器只有 English / Japanese 不足以说明中文补丁或资源存在。检查 NACP 与实际资源，不能承诺中文语音。
- 迁移 S2Arm → NX2Apple 曾备份并传入两份 save 文件，经读回哈希核对，用户确认进度正确。不要假定其他游戏或不同版本也可以直接迁移；目标已有不同存档要先备份。
- 游戏内 Loading 与启动器 shader 预编译是不同阶段。看挂载、资源、线程与 GPU 日志，不能只凭帧率显示就断言卡死原因。

## 图像、性能与输入

- 黑闪需要单变量、同场景对照；XB2 的 Standard 下也有黑闪，不能归因于 MetalFX。用户关闭 Frame buffering 和 Metal 4 pipelines 后表示改善；随后 `DM_PRESENT_LINK=0` 测试下表示消失或明显减少，但结果选项合并了两种情况，且 Encode thread 实际为关闭，尚不能确认根因。设置生效要对照本次启动日志。
- 旧版日志曾显示 MetalFX 从 1280×720 放大到约 2360×1327；这是当次呈现路径和输出，不等于 1080p 内部渲染或所有场景都固定 720p。游戏动态分辨率、重建方式、场景、热量均影响效果。
- 帧率补丁不是插帧，也不自动保证游戏时间步长/过场正常。XB2 Build ID `E3938FA78579C1CA` 的实验补丁是现有社区数据写入的防空指针改写，不是完整 FPSLocker；用户实测速度或帧率异常，已将 enabled 状态清空。原 30 帧需完全退出 App 重启后确认，最后一次记录中用户暂不方便验证。绝不再默认开启。
- 老包的代码页受 iOS 签名限制，运行时数据写入与修改已签名代码不同。做任何 60 帧实验前确认版本、备份存档，明确停止和可验证回退，不覆盖正常版。
- 手柄连接时触控按钮可能按宿主设计隐藏，不等于已支持触屏自动热切换；旧版源码支持前后台暂停/恢复，但系统仍可能回收。用户曾测试截图、短暂切到别的 App 再回来成功；长时间后台与内存压力未验证。

## 证据记录

对每次报错记录引擎/构建版本、设备、游戏 ID 和版本、可复现场景、启动参数、用户操作、日志路径与时间。优先先查同场景正常基线，提出互相可区分的假设；避免将构建耗时、偶发日志或单次对照当成已证实根因。
