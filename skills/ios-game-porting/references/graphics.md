# 画面、MetalFX 和性能

## 先分清实际发生了什么

| 环节 | 含义 | 不应推断 |
|---|---|---|
| 内部渲染分辨率 | 游戏产生画面的像素数，可能动态变化 | 设备屏幕或输出尺寸不代表游戏实际以该分辨率渲染 |
| 空间超分 | 基于当前帧做放大和重建，例如 MetalFX Spatial | 不是增加游戏逻辑帧，也不等于原生高分辨率 |
| 时域超分 | 利用多帧信息，通常还需要运动和深度等输入 | 需要引擎实现，不是打开开关就自动可用 |
| 插帧 | 在已有帧之间合成显示帧 | 不是提高游戏逻辑更新率；可能增加延迟和伪影，具体项目须实现并支持 |
| 60 FPS 补丁 | 改变游戏目标帧率或计时方式 | 不保证 GPU 达标、游戏速度、物理、动画或过场正确 |

[Apple MetalFX](https://developer.apple.com/documentation/metalfx) 提供不同的放大能力；实际系统、GPU、API 与引擎实现可用性要逐一验证。MetalFX 是 Apple 技术，并非本项目提供的开源插件。游戏的 FSR、空间滤波和 MetalFX 是不同实现，不能因设置名称推断其背后真实算法。

## 设置和测试

先记录游戏内分辨率（动态范围如可得）、输出尺寸、帧数统计、GPU/CPU 时间、功耗或热状态、引擎版本、控制器和游戏场景。启动日志若表明 `1280×720 → 2360×1327`，仅证明当次 MetalFX 输入输出，而不是所有场景原生 1080p。

1. 基线：先用当前已知可运行配置，记录同一场景、稳定时间、最低/中位 FPS 和慢帧、时间、温度状态。
2. 每次仅变一个选项（如 Standard/MetalFX、渲染倍率、Frame buffering、Metal 4 pipelines、Encode thread），重启或按实现要求使之生效。查看启动日志核对底层值，界面显示不等于新进程实际使用。
3. 同场景再次测试，记录首次预热与热机结果，保留对照截图或短片；若出现闪烁，区分整个应用界面、游戏画面、局部对象和光影。
4. 黑闪在 Standard 和 MetalFX 都发生时不能断定是 MetalFX 造成；多项设置同时更改时，只能说组合有关。日志中的警告、慢帧或热状态也不是自动证明根因。
5. 恢复可用配置，记录哪些更改保留、怎样回退和尚未证实的假设。修改隐藏环境开关应记录原值；停止游戏、备份配置、确认生效并可恢复。

## shader 与 pipeline

构建期 shader 翻译、Metal 库编译、设备第一次创建 GPU pipeline 是不同阶段。构建显示完成或缓存命中，仍可能在首次进场景编译 pipeline。缓存要与游戏、Build ID、引擎链、编译器和配置匹配；不同引擎的数据结构不保证互通。不能仅靠拷贝旧引擎的 shader 文件保证新引擎画质、帧率或兼容性。

## 60 帧与回退

先查看目标游戏版本和补丁 Build ID，备份存档，确认补丁改变的数据或代码与当前宿主兼容。iOS 已签名代码页与可写数据不同；即使语法被加载也不证明补丁运行正确。比较动作速度、过场、音画、物理、正常游戏时长、FPS 和稳定性；不稳定立即停用，完全退出并重启，再验证恢复基线。不能把补丁失效、设备性能不足、显示刷新率和游戏逻辑锁帧混为一谈。
