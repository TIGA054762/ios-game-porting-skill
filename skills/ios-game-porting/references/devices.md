# 设备与兼容性：先调查，再选方案

## 收集最少必要信息

| 类别 | 核对内容 | 原因 |
|---|---|---|
| iPhone / iPad | 型号、芯片、内存（以官方规格或系统报告为准）、iOS/iPadOS 版本 | 引擎、图形 API、内存和签名能力依设备与系统变化 |
| 存储和状态 | 可用容量、设备温度、后台应用；已安装 App 与最新存档 | 大游戏可能同时需要 IPA、外部数据、解压/传输临时空间；前后台切换可能被系统回收 |
| 电脑 | Windows/macOS、架构、可用容量、工具链和版本、USB | 构建器、SDK、Metal 工具与安装方式因平台和引擎变化 |
| 游戏 | 来源、地区、版本、更新、DLC、Title ID 与 Build ID | 补丁、语言、资源布局和存档不保证跨版本兼容 |
| 目标 | 帧率、清晰度、手柄、续签方式、是否需要多游戏 | 这些会影响引擎和签名方案选择 |

不需要在公开仓库或聊天中提供序列号、UDID、完整配对记录、密码、密钥或证书。分析日志前进行脱敏，公开案例只保留足够复现的技术信息。

## 先区分四个层次

1. **CPU 和系统**：是否支持引擎、宿主应用和签名方式。不同引擎与版本的最低系统要求不同，查具体发布说明。
2. **GPU / Metal 能力**：是否支持相关 Metal 版本、图形功能和 MetalFX 的具体变体；应运行时检测或查 Apple 功能表，不能由宣传名称推断。
3. **内存和功耗**：App 实际内存预算不等于设备总内存；高负载导致降频、掉帧或被系统终止。需要看日志和持续测试。
4. **游戏兼容性**：设备能运行宿主，并不意味着任意游戏或过场都正常。记录版本、区域、可复现位置和验证范围。

## 测试环境

固定游戏场景、时间、分辨率、侧载版本和手柄状态，记录设备冷热与测试时长；优先比较平均帧时间、慢帧与 GPU 时间，而不是只看一瞬间 FPS。首次运行的 shader/pipeline 编译和之后已缓存运行应分开。支持 120 Hz 显示的屏幕也不会自动让 30 FPS 游戏变成 120 FPS。

## 官方入口

- [Apple Metal 功能表](https://developer.apple.com/metal/Metal-Feature-Set-Tables.pdf)
- [Apple 开发者模式](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)
- [NX2Apple](https://github.com/LNPANDY/NX2Apple) 与 [S2Arm](https://github.com/jhaizhou-ops/S2Arm)：版本、支持设备和游戏以各项目当前文档为准。
